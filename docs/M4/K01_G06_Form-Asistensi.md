### Catatan

| Catatan |
| --- |
| 1. *Tujuan utama pembuatan class diagram pada tugas ini adalah untuk mendefinisikan hubungan dan tanggung jawab sistem, bukan untuk mewajibkan gaya pemrograman OOP murni (pendekatan fungsional untuk web development diperbolehkan).* |
| 2. *Terdapat tiga jenis kelas utama: Boundary class (berhubungan dengan sisi client/frontend), Controller class (perantara/API/backend), dan Entity class (data bisnis/database).* |
| 3. *Association: Divisualisasikan dengan garis solid berpanah terbuka (>). Menunjukkan interaksi struktural di mana kelas pemilik mengetahui kelas yang dimiliki (cnth: User berelasi dengan SubscriptionPlan).* |
| 4. *Dependency: Divisualisasikan dengan garis putus-putus berpanah terbuka (>). Menunjukkan penggunaan kelas secara sementara atau sesaat tanpa menyimpannya secara permanen (cnth: RegistrationPage memanggil fungsi EmailValidator).* |
| 5. *Aggregation: Divisualisasikan dengan garis solid berujung belah ketupat kosong di sisi pemilik. Hubungan "has-a" di mana kelas bagian tetap bisa hidup mandiri meskipun kelas pemiliknya dihapus.* |
| 6. *Composition: Divisualisasikan dengan garis solid berujung belah ketupat hitam di sisi pemilik. Hubungan "has-a" mutlak di mana kelas bagian wajib ikut hancur jika kelas pemilik dihapuss.* |
| 7. *Generalization: Divsualisasikan dengan garis solid berujung segitiga kosong dari kelas anak ke kelas induk. Digunakan agar anak mewarisi atribut dan metode dasar dari kelas induk.* |
| 8. *Realization: Divisualisasikan dengan garis putus-putus berujung segitiga kosong dari kelas implementasi ke arah interface yang fungsinya diwajibkan.* |

**Notes for this section:**  
*Catatan dapat dituliskan dalam bentuk paragraf atau poin-poin, disesuaikan saja.*
